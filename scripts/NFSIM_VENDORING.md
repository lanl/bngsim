# NFsim Vendoring

## Goal

BNGsim vendors NFsim from `RuleWorld/nfsim` `master` with a small, explicit
BNGsim carry queue. `bngsim/scripts/vendor_nfsim.py` is the only supported
path that writes `bngsim/third_party/nfsim`.

This doc is BNGsim-specific. The tree under `bngsim/third_party/nfsim` is
generated source. If a change needs to survive the next vendor refresh, land
it in the NFsim checkout first and then re-run `vendor_nfsim.py`.

Paths written `bngsim/...` here, as in the scripts' messages and `VENDOR.json`,
name the bngsim checkout, whatever its directory is called: a worktree such as
`bngsim-wt/<topic>` works the same. (`bngsim/vendor` is the exception: it is
the carry-queue branch in the NFsim candidate checkout, not a path.) Every
`scripts/vendor_*.py` finds the checkout from its own location and acts on
that checkout, so run the copy in the checkout you mean to change (GH #864).

## Current Baseline

- `bngsim/third_party/nfsim/VENDOR.json` currently records source ref
  `bngsim/vendor` at commit `58d50ccf3dcce58fdcac560079bc99d4e5e641a7`. That
  hash is regenerated by every `git am` replay of the patch series, so treat it
  as a record of the last refresh, not as something to reproduce; the tripwire
  matches commit *summaries*, not hashes.
- The two ExprTk shim carries (reserved-symbol remap + mratio) were rewritten
  to **forward** to the host single source `bngsim::expr_compat` rather than
  carry a hand-ported copy of the logic in `bngsim/src/expression.cpp`
  (issue #49). The shim is now a thin mu::Parser adapter; the vendored NFsim
  target links `bngsim::expression` so the shim's `#include
  <bngsim/expr_compat.hpp>` resolves. A third shim carry (GH #771) forwards
  `rint()` to `bngsim::expr_compat::rint` the same way, replacing the shim's
  own `std::round`. A fourth passes the remapped expression through
  `bngsim::expr_compat::exact_literals`, so a numeric literal reads as strtod
  reads it rather than as ExprTk's own number parser does. A fifth refuses a
  bracket right after a call through `bngsim::expr_compat::call_before_bracket`
  (GH #1415). The remaining carries are required local
  carries (selector/exception/build-safety); do not treat them as a new
  upstream retarget.
- The current vendored source is based on upstream `origin/master` commit
  `1a54f38701ab2213de831f9ba272cbb14f7c371f`, the merge of RuleWorld/nfsim `#92`.
  That is deliberately not the `master` tip: the 160 commits that follow it are
  upstream's Aug 29 – Sep 1 performance campaign, which is a separate refresh with
  its own parity run (GH #519 tracks it), not a carry drop.
- Vendoring metadata should record canonical upstream remote
  `https://github.com/RuleWorld/nfsim.git`.
- Every carry in the queue is still live, because the base is still
  `1a54f387`. Upstream v2.0.1 (`bc0a025a`, released 2026-11-25) holds its own
  versions of most of them. "Upstream Status (v2.0.1)" below says which carries a
  refresh to it drops, which ones it changes, and which it keeps (GH #519). The
  earlier carries behind RuleWorld/nfsim PRs `#69`, `#70`, `#72`, `#73`, `#74`,
  `#80`, `#81`, `#82`, `#89`, and `#92` are in upstream `origin/master` and
  should stay out of the local carry queue.
- RuleWorld/nfsim `#92` merged on 2026-08-31 and took the TotalRate symmetry
  carry upstream (GH #426, GH #428). The queue went from 14 carries to 13 and the
  base moved to that merge commit. Upstream's version is the same guard; only
  the comment above it was reworded in review.
- RuleWorld/nfsim `#89` merged on 2026-08-18 and took four carries upstream at
  once: multi-bond product molecularity, Species-observable complex tracking,
  the symmetry factor on every rate law, and pure-context per-complex counting
  (GH #410). The queue went from 17 carries to 13. Upstream's version of the
  pure-context fix is a superset of the carry it replaces — it also handles
  `exactRuleMonkey_a()`, which is unreachable here because the vendor export
  trims `src/NFsim.cpp`. That refresh also picked up upstream `#88`, a
  precision fix in the MM rate law, which upstream's symmetry commit is
  written on top of. The symmetry commit in that batch also carried a defect
  upstream: it applied the factor to TotalRate rules, which state their whole
  propensity outright and so have no match count to correct. That was fixed
  upstream by `#92` (GH #426) and is no longer a carry.
- `bngsim/vendor-next` is retired. Do not use or recreate it.

If this doc and `VENDOR.json` disagree, trust `VENDOR.json`.

## Source Of Truth

- `origin/master`: upstream NFsim base
- `bngsim/vendor`: single active NFsim integration branch used for vendoring
- `bngsim/scripts/vendor_nfsim.py`: only supported exporter into
  `bngsim/third_party/nfsim`
- `bngsim/third_party/nfsim/VENDOR.json`: authoritative record of source
  commit, upstream base, and live carry queue
- `bngsim/scripts/nfsim_vendor_patches/`: restartable export of
  `origin/master..bngsim/vendor`

Historical branches such as `bngsim/connected-update`,
`bngsim/vendor-build`, `bngsim/tfun`, `bngsim/step-to-cache`,
`bngsim/windows-nauty`, `bngsim/embedding-api`, and `bngsim/library-build`
are provenance only unless you are doing archaeology.

  and MatchOnce is applied to DOR rules too (GH #1525)
- a bond partner of the wrong molecule type rejected before its component arrays
  are indexed with a component index belonging to the PARTNER template's type,
  which reads out of bounds on a shorter molecule. Four sites: the normal and
  symmetric branches of `checkBonds` and of `checkSymmetricComponents`, the
  symmetric ones through `tryToMap()`. The type check exists in `compare()` but
  is reached after the reads. Results are unaffected either way; the read is
  undefined behaviour and faults when the array ends at an unmapped page. All
  four sites are reachable and all four fault under AddressSanitizer, with a
  fixture each under `tests/data/nfsim/`. The three beyond `checkBonds`' normal
  branch each need a symmetric component off the reaction centre, on a side that
  differs by site: the partner's for `checkBonds`' `tryToMap()` branch; the
  matched molecule's own, with a concrete partner index, for
  `checkSymmetricComponents`' normal branch; and both for
  `checkSymmetricComponents`' `tryToMap()` branch, since that function's loop
  runs over the matched template's own symmetric components and so is not
  entered without own-side symmetry. Nothing in a 54-model sweep has that, so
  the sweep's zero hits say nothing about reachability. A positive fixture holds
  the `checkSymmetricComponents` guard to `continue`: `return false` there
  abandons the rest of the equivalency class and loses a match origin/main keeps
  (GH #1543; submitted upstream as RuleWorld/nfsim#113)
- product molecularity tested as BioNetGen tests it: no two molecules a rule
  acts on that map to different product patterns may stay connected once its
  deleted bonds and molecules are gone (a bond it adds joins molecules of one
  pattern), for any number of reactants and whatever `-cb` says. The loader records each reactant
  molecule's product pattern from the rule's `Map`; `finalize()` records the
  molecules a rule acts on and the ones it deletes (BNG2.pl writes no
  `DeleteBond` for a deleted molecule's bonds). Upstream's test (issue #48) ran
  for one-reactant rules under `-cb` only, between the ends of each deleted
  bond, so without `-cb` a ring bond broke, bimolecular and three-product splits
  fired on rings, and a rule deleting a bond inside one pattern, or a molecule
  bridging its products, never fired. Not tested yet: a product held apart only
  by a deleted molecule, or tied to its pattern only by `.` (neither has a
  molecule the rule acts on), and `ensureConnected`. Same carry: `getListOfProducts`
  lists each molecule once (without `-cb`, two reactants in one complex listed
  shared neighbours twice and inflated the Molecules observables)
- a rate that reads an observable held until a firing is done: a firing takes
  its products out of their observables, transforms them, puts them back, and
  then puts them back in their reactions one at a time, and a rate law read in
  between is read at a state the system is never in. With one X,
  `kgap*(1+9*Xp/Xtot)` was 0/0 there; the NaN stayed in NFsim's running total
  and the run froze at the first X firing with no error (GH #1818). This is
  RuleWorld/nfsim#117, merged upstream as `a0bf9134`, written against the
  pinned base, which has no `selector->updateBatch` and no shared
  `Observable::updateDependentReactions`. Drop it when the base moves past
  `a0bf9134` (GH #519)
- the selector's running total propensity kept from drifting off the sum of the
  propensities, and a reaction fired at any total above 0. The total is a
  running sum, `Atot - oldA + newA`, and a propensity added to a large total is
  rounded to its spacing and not given back when the large term is taken off: a
  slow channel at 1e-6 beside a fast one at 1e11 was lost once the fast one was
  0, and beside one at 1e10 fired at 1.9 times its rate (GH #1666). The sum
  also drifts without a fall where the roundings fall the same way every time,
  and the reaction listed last loses what it has lost. `DirectSelector` sums it
  afresh from each reaction's `get_a()` once it has fallen below 2^-10 of the
  largest value it has held since it was last summed, or below 0, or has taken
  2^12 updates since then, which holds it within about 2^-40 of its peak: well
  below the 2^-32 a pick is drawn to near the peak, and 2^-30 of a total at
  2^-10 of it; `System::a_tot` follows the selector after each pick. The tests
  are made where the total is read, before a waiting time is drawn
  (`ReactionSelector::getAtotForDraw()`) and before a pick, not in `update()`,
  so a total that dips and comes back within a firing costs no pass over the
  reactions. Each sum is a pass over all N reactions, so a model whose total
  keeps falling 1024-fold slows at least in proportion to N, and more once the
  reactions no longer fit in cache: one A flipping at 1e6 and back at 1e-3
  beside 10,000 births at 1e-9 ran 17 to 28 times as long, on two machines. A
  total that is not finite is kept, for the host's check to refuse. `stepTo`,
  `sim` and `singleStep` fired nothing at a total of 1e-9 or less
  (`ATOT_TOLERANCE`), a rate in the model's own time unit (GH #1672); they test
  `a_tot > 0` now, and the selector picks nothing from a total that is not
  above 0. This is RuleWorld/nfsim#123, fixed upstream by RuleWorld/nfsim#128,
  merged as `7501f675`, written against the pinned base. Upstream makes the
  same test of the fall before a waiting time is drawn and has the rest, but no
  count, which RuleWorld/nfsim#130 asks it for: at `7501f675`
  `drifting_flip.xml` still loses 2.2e-16 a cycle and its last reaction is
  lost. The carry also keeps the peak at every update, tests before a pick too,
  and on an empty pick has `stepTo` draw again rather than stop, as the
  time-table carry above needs. When the base moves past `7501f675`, reduce it
  to the count, moving `stepTo`'s redraw on an empty pick into the time-table
  carry (upstream's `stepTo` goes to the stopping time there), and drop it only
  once RuleWorld/nfsim#130 is fixed upstream (GH #519)

Not a carry, but tied to the vendored NFsim: bngsim refuses, by name, the rate
laws NFsim cannot run, in `python/bngsim/_network_free_checks.py`
(`refuse_nfsim_rate_laws`). A Michaelis-Menten rule with a reactant counted once per
complex (a whole-complex deletion or MatchOnce) whose complex may hold two
matches is refused there too: the law is not linear in its counts, so the
thinning above cannot correct it (GH #1525). Arrhenius (energy-based) rules are refused because
NFsim's energy-rule expansion divides by an `RT` BioNetGen does not apply and
gets one-way and state-change rules wrong (RuleWorld/nfsim#102); when a refresh
brings in the upstream fix, drop that half and test NFsim against the generated
network instead (gated issue #1057 lists the steps). A rate-law type outside Ele, MM, Function and FunctionProduct
is refused because NFsim implements none: it drops a Hill rule silently (upstream v2.0.1
refuses it at load, RuleWorld/nfsim#135).

Dropped carries that are now upstream include connectivity determinism,
observable-output accessors, NFsim's library-build/export toggles, the old
`stepTo()` cache carries, the ExprTk snapshot refresh, the recent
`resetConcentrations()` / selector-teardown fixes, and the four correctness
fixes RuleWorld/nfsim `#89` absorbed (product molecularity for multi-bond
ring-opening, Species-observable complex tracking, the symmetry factor on
every rate law, and pure-context per-complex counting), and the TotalRate
exemption from that symmetry factor that RuleWorld/nfsim `#92` took (GH #426).

Keep this queue small, reviewable, and easy to drop. When upstream absorbs a
carry or BNGsim no longer depends on it, remove it from the queue and rebuild
`bngsim/vendor` from a clean `origin/master` base.

Direct edits to `bngsim/third_party/nfsim/` are not supported and have caused
two production regressions (Session 29's exit→throw work and the stepTo cache
fix were both lost). If a change needs to survive, land it in the NFsim
checkout on the `bngsim/vendor` branch first, regenerate the patch series
under `bngsim/scripts/nfsim_vendor_patches/`, and re-run `vendor_nfsim.py`.

## Safe Workspace Policy

- Prefer `/tmp/nfsim-vendor-candidate` for vendoring work.
- Prefer cloning directly from `https://github.com/RuleWorld/nfsim.git`.
- If you bootstrap the candidate from another local checkout for convenience or
  offline work, treat that checkout as transport only.
- Immediately reset the candidate checkout's `origin` remote to
  `https://github.com/RuleWorld/nfsim.git` before running
  `vendor_nfsim.py`. That keeps `VENDOR.json` metadata canonical.
- Do not treat a found build tree as proof. Validate through the repo-supported
  build/test flows below.

## Rebuild The Candidate Checkout

Fresh clone from the canonical upstream remote:

```sh
BNGSIM_ROOT=/path/to/bngsim   # this checkout, whatever its directory is called
git clone https://github.com/RuleWorld/nfsim.git /tmp/nfsim-vendor-candidate
git -C /tmp/nfsim-vendor-candidate fetch origin --prune
git -C /tmp/nfsim-vendor-candidate checkout -B bngsim/vendor origin/master
git -C /tmp/nfsim-vendor-candidate am \
  "$BNGSIM_ROOT"/scripts/nfsim_vendor_patches/*.patch
git -C /tmp/nfsim-vendor-candidate status --short --branch
```

Optional bootstrap from a local cache checkout:

```sh
BNGSIM_ROOT=/path/to/bngsim   # this checkout, whatever its directory is called
git clone /path/to/nfsim-cache /tmp/nfsim-vendor-candidate
git -C /tmp/nfsim-vendor-candidate remote set-url origin https://github.com/RuleWorld/nfsim.git
git -C /tmp/nfsim-vendor-candidate fetch origin --prune
git -C /tmp/nfsim-vendor-candidate checkout -B bngsim/vendor origin/master
git -C /tmp/nfsim-vendor-candidate am \
  "$BNGSIM_ROOT"/scripts/nfsim_vendor_patches/*.patch
git -C /tmp/nfsim-vendor-candidate status --short --branch
```

The local clone may inherit a different default branch from the source repo.
The `checkout -B ... origin/master` step above resets it to the intended clean
base.

## Standard Refresh Workflow

replaying the explicit carries instead of stacking more ad hoc commits on top
of an old vendor branch. While the base is pinned behind the `master` tip (see
the baseline note above), check out the `base_commit` recorded in
`VENDOR.json` instead of `origin/master`; the tripwire's strict mode rebuilds
from the merge base with `origin/master`, so it verifies either way:

```sh
BNGSIM_ROOT=/path/to/bngsim   # this checkout, whatever its directory is called
git -C /tmp/nfsim-vendor-candidate fetch origin --prune
git -C /tmp/nfsim-vendor-candidate checkout -B bngsim/vendor origin/master
git -C /tmp/nfsim-vendor-candidate am \
  "$BNGSIM_ROOT"/scripts/nfsim_vendor_patches/*.patch
```

### 2. Preview Before Writing

From inside the checkout, drop the `bngsim/` prefix. As written, the commands
assume a checkout named `bngsim` and run from the directory above it; from the
directory above a checkout with another name, `bngsim/scripts/...` is some
other checkout's script, and it would act on that checkout.

```sh
python3 bngsim/scripts/vendor_nfsim.py \
  --nfsim-repo /tmp/nfsim-vendor-candidate \
  --ref bngsim/vendor \
  --summary --compare-ref origin/master

python3 bngsim/scripts/vendor_nfsim.py \
  --nfsim-repo /tmp/nfsim-vendor-candidate \
  --ref bngsim/vendor \
  --check
```

The goal is a small, understandable delta versus `origin/master`. If the delta
is unexpectedly large, stop and inspect the carry queue before rewriting the
vendored tree.

### 3. Refresh `bngsim/third_party/nfsim`

```sh
python3 bngsim/scripts/vendor_nfsim.py \
  --nfsim-repo /tmp/nfsim-vendor-candidate \
  --ref bngsim/vendor
```

This updates:

- `bngsim/third_party/nfsim`
- `bngsim/third_party/nfsim/VENDOR.json`

It refuses to write if `bngsim/third_party/nfsim/` has uncommitted changes —
including untracked files — since the refresh replaces the tree wholesale.
Commit or stash them; `--force` overrides the check but does not make the
overwrite recoverable.

### 4. Validate Inside BNGsim

Use the repo-supported flows and re-run the NFsim-specific surface:

```sh

  python/tests/test_nfsim.py \
```

Prefer `ninja`-backed builds when the local generator supports it, but treat

Editable-build reminder:

- `uv run --directory bngsim python -m pytest ...` uses the installed editable
  extension, and editable imports do not auto-rebuild.
- If Python results disagree with the current C++ source tree, compare the
  `_bngsim_core` binary timestamp to the edited source files and rebuild the
  runtime before trusting the failure.
- On this macOS setup, `uv run python bngsim/scripts/rebuild_editable.py` can
  still fail for unrelated mixed-architecture linker reasons. When that
  happens, validate the current runtime through a fresh wheel build instead of
  trusting a stale editable `.so`.

## Restart Artifacts

The restart bundle is the patch series in `bngsim/scripts/nfsim_vendor_patches/`.

After any intentional change to `bngsim/vendor`, regenerate the patch export:

```sh
BNGSIM_ROOT=/path/to/bngsim   # this checkout, whatever its directory is called
rm -f "$BNGSIM_ROOT"/scripts/nfsim_vendor_patches/*.patch

  -o "$BNGSIM_ROOT"/scripts/nfsim_vendor_patches \
  origin/master..bngsim/vendor
```

Then refresh the handoff note so the recorded tip, base, and validation
commands still match reality.

## Tripwire (`--verify-clean`)

`vendor_nfsim.py --verify-clean` is the CI-side tripwire that catches
direct edits to `bngsim/third_party/nfsim/`. It performs two checks:

1. **Byte-match.** Exports the tree the candidate's `bngsim/vendor` tip
   would produce and compares it against `bngsim/third_party/nfsim/`.
   Any divergence is reported as `DIRECT EDIT DETECTED` with the list of
   changed files and the standard remediation message.
2. **Carry-queue ↔ patch series cross-check.** Confirms that the number
   of `*.patch` files under `bngsim/scripts/nfsim_vendor_patches/`
   matches `len(commit for topic in CARRY_QUEUE for commit in topic)`,
   and that every commit summary listed in `CARRY_QUEUE` matches some
   patch's `Subject:` line. Catches "added a topic to `CARRY_QUEUE`
   without re-exporting the patch series" and similar drift.

```sh
python3 bngsim/scripts/vendor_nfsim.py \
  --nfsim-repo /tmp/nfsim-vendor-candidate \
  --verify-clean
```

Add `--strict` to additionally rebuild the candidate from scratch
(`origin/master` + `git am` of the patch series in a temp checkout) and
confirm the result matches the live candidate's `bngsim/vendor` tip —
i.e., that the patch series is reproducible end-to-end.

```sh
python3 bngsim/scripts/vendor_nfsim.py \
  --nfsim-repo /tmp/nfsim-vendor-candidate \
  --verify-clean --strict
```

The tripwire is also wired into the local-CI pre-commit hooks:

```sh
pre-commit run --hook-stage manual local-ci-vendor-verify
pre-commit run --hook-stage manual local-ci-vendor-verify-strict
```

CI runs it on every pull request and push to `main`: the `nfsim-vendor` job in
`.github/workflows/lint.yml` replays the patch series onto the `base_commit`
`VENDOR.json` records and runs `--verify-clean` against that candidate. Until
it did, nothing ran the tripwire outside the manual stage, and GH #1419's edit
to `nfsim_funcparser.h` landed as a direct edit.

When the tripwire fires, do not bypass it. Drift means a direct edit
slipped through; follow the remediation message — land the change on
`bngsim/vendor`, re-export the patch series, update `CARRY_QUEUE`,
re-run `vendor_nfsim.py`.

Preview the impact without writing:

```sh
python3 bngsim/scripts/vendor_nfsim.py \
  --nfsim-repo /tmp/nfsim-vendor-candidate \
  --ref bngsim/vendor \
  --summary --compare-ref origin/master
```

The script records source metadata in `bngsim/third_party/nfsim/VENDOR.json`.
The no-argument form targets `/tmp/nfsim-vendor-candidate` plus
`bngsim/vendor`, but the explicit `--nfsim-repo` / `--ref` form is clearer in
shared notes and transcripts.

If your NFsim checkout lives somewhere else, point the script at it:

```sh
python3 bngsim/scripts/vendor_nfsim.py --nfsim-repo /path/to/nfsim
```

If you need to bypass automatic ref resolution, an explicit fully-qualified ref
also works:

```sh
python3 bngsim/scripts/vendor_nfsim.py --ref refs/heads/bngsim/vendor
```

## Pruning Rules

The vendored import includes:

- `CMakeLists.txt`
- `LICENSE.txt`
- `README.md`
- `src/`

The vendored import excludes:

- `src/NFtest`
- `src/NFfunction/muParser`
- `src/NFfunction/exprtk` (GH #126 — see "NFsim's ExprTk Copy" below)
- `src/NFutil/MTrand/mttest.cpp`

These rules are encoded in `bngsim/scripts/vendor_nfsim.py` and should be
changed there first if the vendor surface changes.

The vendored `bngsim/third_party/nfsim/README.md` is copied from the NFsim
source branch during refresh. If you want that file's maintainer guidance to
survive the next vendor sync, update it in the NFsim source checkout first and
then re-run `vendor_nfsim.py`.

## NFsim's ExprTk Copy

- Upstream NFsim vendors its own `src/NFfunction/exprtk/exprtk.hpp`, but BNGsim
  **prunes it from the vendor export** (`PRUNED_PATHS` /
  `VENDOR.json` `excluded_paths`) — GH #126, the file-level half of the GH #49
  ExprTk convergence (ADR-005 collapsed the duplicated *logic*; #126 collapses
  the duplicated *file*).
- The NFsim build is configured with `NFSIM_USE_EXPRTK=ON`, so the `mu::Parser`
  shim (`src/NFfunction/nfsim_funcparser.h`) still does `#include "exprtk.hpp"`.
  After the prune that include resolves against the **single host snapshot**
  `bngsim/third_party/exprtk/exprtk.hpp`: the parent `CMakeLists.txt` adds
  `${BNGSIM_EXPRTK_DIR}` to the `NFsim_objects` / `nfsim` target include paths
  right where it already links `bngsim::expression` into them (issue #49 wiring).
  No vendor carry is involved — the redirect is host build configuration, the
  same place that already forces `NFSIM_USE_EXPRTK` and the library/executable
  toggles.
- The vendored `third_party/nfsim/CMakeLists.txt` still appends its (now-absent)
  `src/NFfunction/exprtk` to the include path (the `NFSIM_USE_EXPRTK` branch at
  lines ~69 / ~143). That is a harmless dead `-I` the compiler ignores — exactly
  the long-standing pattern for the already-pruned `src/NFfunction/muParser`
  dir — so it is left untouched rather than carried.
- There is now **one** `exprtk.hpp` per binary. Refreshing
  `bngsim/third_party/exprtk` (via `vendor_exprtk.py`) is the single place an
  ExprTk snapshot bump happens; the ODE/SSA engine, RuleMonkey, and the NFsim
  shim all compile against it. The former byte-drift guard
  `test_exprtk_reserved_consistency.py` is retired — there is no second copy to
  drift against.
