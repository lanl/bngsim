- **Compiled code read `not(k)^n` as `not(k^n)`** ([#1506](https://github.com/lanl/bngsim/issues/1506)). ExprTk parses `not` as a call, so `not(k)^n` is `(not(k))^n`; the C generator wrote it as C's prefix `!` and the power went inside it. At `k = n = 0` that is 0 where the interpreter has 1, and a species fed at that rate reached 0 instead of 10 with no warning; the readings also differ at a negative exponent, and where `k^n` underflows. `2^not(k)` emitted C that did not compile. `not(x)` is now written whole, as ExprTk's `notl_impl`, so it is one operand on either side of a `^`.
