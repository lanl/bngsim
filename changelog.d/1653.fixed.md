- **A `.net` file that is not UTF-8 failed with a bare `UnicodeDecodeError` ([#1653](https://github.com/lanl/bngsim/issues/1653)).** A species name saved in Latin-1 (`Aµ()`, the byte 0xb5) loaded, and its name then raised an error that named neither the file nor the line; a refusal quoting such a line lost its words to the same error. `Model.from_net` and `parse_net_file` now refuse a line of the five blocks that is not UTF-8 with the `ModelError` and `ValueError` they document, quoting the line with the byte shown as `\xb5`, and show such a byte the same way in any other refusal, the table-function reader's of a table file among them. A byte in a comment, a block passed over or an action line still loads. `write_net` now writes UTF-8 whatever the locale: under a Latin-1 or cp1252 locale (Windows) it wrote such a byte, and could not write a name outside that encoding at all.
