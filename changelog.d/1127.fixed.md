- **A pulse written with `%` is no longer stepped over (issue #1127).**
  ExprTk's `%` on doubles is `fmod`, the same as its `mod()`, but the crossing
  stops (#869) and state-switch roots (#1068) read named calls only, so
  `((Tobs+49.99)%100)-((Tobs+50)%100)+0.01` in a `.net` rate law got neither and
  a run returned Y = 0 with no error where `mod()` gave 3.934694. The model
  builder now spells every `a % b` in a function body as `mod(a, b)`, with `%`
  binding like `*` and `/`, left to right; the values are unchanged to the bit.
  The same change lets `codegen=True` compile such a model, which failed
  before (`%` on two doubles is not C). A model with its own symbol named
  `mod` keeps its text.
