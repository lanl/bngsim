- **`run_protocol` could leave a derived parameter a number after `resetParameters`, in some runs and not in others ([#1870](https://github.com/lanl/bngsim/issues/1870)).** The reset re-attaches each derived parameter a `setParameter` overrode since the save by writing back its saved value, which works only once the parameters it reads are back. They were written in the order of a set, so one written before a parameter it reads stayed a number and stopped following; the order follows the string hash seed. With `k2 k1*0.5` and `k3 k2*2` both overridden, then reset, `setParameter("k1",3)` left k3 at 1 under `PYTHONHASHSEED` 0 and moved it to 3 under 1: Ctot(0.5) was 12.3121 or 29.1667, where BNG2.pl gives 29.1667. The saved values are now written back twice, in the model's order: after the first every value is back, so at the second each expression gives its own.
