- **Under a decimal-comma `LC_NUMERIC` (`de_DE`, `fr_FR`), the C++ side read `0.5` as `0`** ([#1235](https://github.com/lanl/bngsim/issues/1235)). A process that had called `setlocale` on a German or French machine had a homodimer's stat factor `0.5*kf1`, which BNG2.pl writes for every homodimer, refused as an unknown parameter; a group factor `0.5*1,2` read 0 and an inline table's 2.5 read 2, with no error; literals ExprTk misreads went one ulp off again (#1014); and the SSA propensity source wrote `0,5` into its C. Every number the C++ side reads (the .net loader, expression literals, seed rounding, the parameter-override XML, four environment variables) and every one it writes for a parser to read back (expression literals, the SSA propensity source, the override XML) is now read and written in the "C" locale, whatever the process's. libantimony has the same fault (`k = 0.1` reached its SBML as 0), so `from_antimony` and `from_antimony_string` call it under a "C" `LC_NUMERIC` and put the caller's back.
