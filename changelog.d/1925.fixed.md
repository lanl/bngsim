- **`Simulator(sensitivity_params=..., sensitivity_ic=...)` reported a name the model does not have only once the run had started, as a failed run (issue #1925).** The run raised `SimulationError` with the code `run.failed`. A single name passed as a string (`sensitivity_params="k1"`), a set or a dict met a raw pybind11 `TypeError` there instead, and a NumPy array of two or more names a raw `ValueError` at once. The Simulator now refuses each when it is made. A missing name raises the error class and code `set_param` or `set_concentration` raises for it: `ParameterError` (`param.not_found`) or `ModelError` (`species.not_found`), with its close matches. A species given as a parameter, a parameter as a species, and an observable of one species are pointed at the keyword that takes them, by the model's own spelling (`'X' is the species 'X()'`). A string, a set, a dict or a name that is not a string raises `ArgumentTypeError` (`usage.wrong_type`); any other iterable of names, a NumPy array included, is taken in its order. On the command line, each is a usage error that names the option.
