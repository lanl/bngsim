- **`Simulator(sensitivity_params=..., sensitivity_ic=...)` and `steady_state(sensitivity_params=...)` reported a name the model does not have only once the solve had started, as a failed run (`run.failed`) (issue #1925).** A single name passed as a string met a raw pybind11 `TypeError` there (`steady_state` read it as one-letter names), as a dict did, and a NumPy array of two or more names a raw `ValueError`. Each call now refuses a missing name at once, with the error class and code `set_param` or `set_concentration` raises for it (`ParameterError` `param.not_found`, `ModelError` `species.not_found`) and its close matches. A species given as a parameter, a parameter as a species, and an observable of one species are pointed at the keyword that takes them, by the model's own spelling. A string, bytes, a value that does not iterate and a name that is not a string raise `ArgumentTypeError` (`usage.wrong_type`), so `[b"k1"]`, which ran, is now refused. A false value is no names, as before, and anything else that iterates (a dict's keys, a set, a NumPy array) is taken in its order.
