- **An ODE output point too close to where the run stands no longer silently takes the start state where the model moves.** CVODE does not integrate over less than about twice the doubles' spacing, and such an output was taken as reached (issue #1501). Far from 0 that is wide: over `(1e17, 1e17 + 64)`, where the doubles are 16 apart, `A -> B` at `k = 1` came back B = 0 at t0 + 16 and t0 + 32, where B is 1, and over `(1e17, 1e17 + 10)` its 11 output times rounded onto two, every row B = 0, with no error or warning. Such an output is now `UsageError` (`usage.span_out_of_reach`) where a species would move past its tolerance over the distance, and a grid finer than the doubles across it is refused before it runs. Repeated sample times, and an output where the model barely moves, keep their rows.
