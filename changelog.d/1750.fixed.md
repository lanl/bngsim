- **A protocol given numpy values could not be written, and was written or run wrong in four other ways ([#1750](https://github.com/lanl/bngsim/issues/1750)).** A step may hold a seed from `rng.integers()`, an `n_points` or a sweep from `np.linspace`. `run_protocol` ran it, but `ProtocolSpec.to_json` and `write_sedml_protocol` raised `TypeError: Object of type int64 is not JSON serializable` (float32 values and numpy bools did too). `write_bngl_protocol` wrote an int64 seed as the string `seed=>"42"` and a numpy bool as `"True"` or `"False"`, both true to Perl. The SED-ML left out a uint64 seed it read as a float, and a scan's float32 bounds made float32 points, in the run and in the SED-ML. A `StateChange` and an `Experiment` now hold the Python value a numpy value holds, as `EvaluationSpec` holds its seed, so each writes and runs as the same protocol with Python numbers. And an integer seed above 2**53, numpy or not, now goes through the actions block exactly: `write_bngl_protocol` wrote 2**64 - 1 as 2**64, out of a seed's range, and `parse_bngl_protocol` read it so.
