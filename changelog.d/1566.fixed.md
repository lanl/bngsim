- **A forward-sensitivity run on BIOMD0000000471 built its compiled library in about 100 s and then crashed the process on its first step ([#1566](https://github.com/lanl/bngsim/issues/1566)).** Its 54 MB source compiles at `-O0`, where the compiler gives every temporary in a function its own stack slot, and its `bngsim_dfdp` reserved a 12.2 MiB stack frame, more than the 8 MiB stack of the macOS main thread. Every gcc/clang codegen compile now asks the compiler to report a function whose frame is over 4 MiB, and such a library is refused, not installed. A plain run then falls back to the interpreted RHS, as on any failed build. A sensitivity run, which needs the library, refuses with a message that names the function and its frame and suggests `BNGSIM_CODEGEN_OPT=1`. Libraries whose frames fit build as before, BIOMD0000000496's 2 MB `-O0` frame among them. MSVC gives no such report outside `/analyze`, so a Windows `cl` build is not checked.
