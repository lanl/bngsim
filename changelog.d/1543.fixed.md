- **An out-of-bounds read in the vendored NFsim's pattern matcher could crash a network-free run.** `checkBonds` and `checkSymmetricComponents` index a bond partner's component arrays with an index belonging to the *partner template's* molecule type -- directly in their normal branches, through `tryToMap()` in their symmetric ones -- before anything has checked the molecule is of that type; `compare()` checks it, but only after the reads. A shorter partner is read past the end: in `tcr.bngl` a ZAP70 whose partner template is LCP2 (4 components) matched a bond to a LAT (2 components) and read index 3, which AddressSanitizer reports as a heap-buffer-overflow. Results were unaffected -- the match is rejected either way -- but the read is undefined behaviour that faults only when the array ends at an unmapped page, so it was an intermittent crash: it killed a 210-model network-free parity run after 185 minutes. A guard above each function's branch dispatch now answers the type question before any index is used, covering all four sites, each with a fixture that faults under AddressSanitizer on the unfixed engine. Vendor patch 0023; submitted upstream as RuleWorld/nfsim#113.
