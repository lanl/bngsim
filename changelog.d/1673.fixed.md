- **An ODE row on the instant a counter reaches an event's threshold read the state before or after the event according to the run's length ([#1673](https://github.com/lanl/bngsim/issues/1673)).** `x(0) = 0.1`, `x' = 1`, `at (x >= 2.6): S = 1`: the row at t = 2.5 read S = 3 for `t_end` in (2.5, 4] and (32, 64], and S = 1 for (4, 32], with nothing else changed. The crossing time came from a two-point solve over a power of two at or above the run's end, which in doubles moves by an ulp with that scale. For a trigger whose truth changes where its residual first reaches 0 (`>=` or `<` on a rising counter, `>` or `<=` on a falling one) it is now moved to the first double at which the residual, as bngsim's threshold evaluator computes it, is 0 (or the nearest where none is), so the stop and the row no longer move with the run's length, and a row on that first zero holds the state after the event (#1124). So is one written with `abs()` or a square (`abs(x - 3.1) <= 0.5`), whose edges had been registered as strict. Solved over the crossing's own scale, not the run's end, a strict `x > 2.6`, `==` or `!=` also stops at one double for every run length.
