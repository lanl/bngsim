- **Forward-sensitivity refusals that turn on which parameters are requested came back as a plain `SimulationError`**, which a fitting driver or a parity suite could tell from a solver crash only by its text (issues #1435, #1560). These are the solver's refusals partway through a run where a requested parameter moves a crossing or a fire, moves two times apart, or moves the run onto an edge, so the result has a kink or a jump and no derivative. They now raise `SensitivityRefusedForParametersError`, a `SensitivityRefusedDuringRunError`, so they are a `SensitivityUnsupportedError` and still the `SimulationError` an existing `except` caught. `compute_all_sensitivities` still retries a chunk refused this way one column at a time, and now raises the same type, saying which columns are refused alone and which ran, without the advice to loosen the tolerances that suits a solver failure. One run-time message stays untyped on purpose: a fire the solver found but did not locate, which asks for the model to be reported.
