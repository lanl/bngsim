- **Compiled code divided two comparisons as C ints** ([#1495](https://github.com/lanl/bngsim/issues/1495)). C computes a comparison or a logical operator as an `int`, where ExprTk and the interpreter have a double, 1 or 0. So a quotient made only of them divided as ints: `share() = ((A>thr)+(B>thr))/((A>0)+(B>0))` was 1/2 = 0 compiled and 0.5 interpreted, and a species fed at that rate reached 0 instead of 5, with no warning, under `codegen=True`, on every forward-sensitivity run, and by default once a model has 256 species. `(A>thr)/(C>thr)` with `C` below `thr` divided an int by zero, which is undefined in C where the interpreter refuses an inf, and `-(C>thr)` lost the sign of a zero. Each comparison or logical result that arithmetic reads is now a double, and ExprTk's `&` and `|` are written as the `and` and `or` they are. The JAX translation used by `jacobian="jax"` had the same fault in its own form: JAX adds two booleans as a logical or, so `(A>0)+(B>0)` was 1, and it refused `-(A>B)`; it too now reads a comparison as a double where arithmetic does.
