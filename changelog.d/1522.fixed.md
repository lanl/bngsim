- **SBML `quotient` and `rem` truncate, as MathML defines them** ([#1522](https://github.com/lanl/bngsim/issues/1522)). Both of the loader's MathML translators floored, so a negative operand gave the wrong integer: `quotient(-5, 3)` read -2 and `rem(-5, 3)` read 1, where SBML (through MathML 2.0), libRoadRunner and COPASI give -1 and -2. This held in assignment rules, kinetic laws and initialAssignments, interpreted and compiled, and in a `.net` that `bngsim.convert` wrote. Both now truncate, in the form libSBML writes its own `%`, a sign test choosing `ceil` or `floor`, which bngsim already read everywhere a floor is read. Where both operands are non-negative numbers by their form, the floor alone is still written, so those laws run as before. An operand that reads the time takes the sign test, since a run can start before 0: a far line through the clock, `quotient(1e10 + time, 0.01)`, is now refused by name by #1018's reading, where it ran exactly from 0. Over a clock offset by a start time, `rem(time - t0, P) >= d` was on before `t0`; it now is not, and a sensitivity run of it is refused by name rather than compensated as that schedule.
