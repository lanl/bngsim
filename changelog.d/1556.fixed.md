- **On Python 3.13 and later, a stop condition whose arithmetic hit 0/0, a division by zero or an overflow refused the run** ([#1556](https://github.com/lanl/bngsim/issues/1556)). numpy's warning, issued inside the condition, raised `KeyError: '__import__'`, and the run stopped with "could not be evaluated". Each such sample is now read at the value numpy gives it (NaN is not met, +inf is where the condition reads `> 0`), and each run checked issues one `RuntimeWarning` that names the condition and the error, on every Python. numpy's own settings are kept: an error set to ignore, print, raise, call or log is handled as numpy would. Another warning issued inside a condition where Python would show it, such as numpy's `ComplexWarning`, still refuses the run on 3.13, now with a message that says why.
