- **Most forward-sensitivity refusals the solver reaches during a run came back as a plain `SimulationError`**, which a fitting driver or a parity suite could tell from a solver crash only by its text (BIOMD0000000285's AMICI sensitivity row scored as a crash). The 16 reached whatever parameters are requested (a trigger leaving its threshold flat, a compartment jumping twice at one instant, a delay a `run_batch` row made positive, an event triggered by another's assignment, and the like) now raise `SensitivityRefusedDuringRunError`: a `SensitivityUnsupportedError`, and still the `SimulationError` an existing `except` caught. `compute_all_sensitivities` raises them at once instead of retrying every column alone first. Refusals that turn on which parameters are requested are unchanged. A wall-clock timeout in the run that confirms the order of a switch and an event is now a `SimulationTimeout`, not a refusal of the order.
