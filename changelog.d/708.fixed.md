- **Forward sensitivities after a derived parameter is overridden or re-attached** (#708). The compiled sensitivity code carries the chain rule through a derived parameter while it follows its expression and not while `set_param` has pinned it, and code built for one case was kept across the write: by the Simulator that held it, by a new Simulator on the same model, by a clone, and by `run_batch` rows. For `k2 = 2*k1` and a rate `k2*A*A`, pinning `k2` at 5 returned dA/dk1 = -0.0769 for 0, and attaching it again returned 0 for -0.4535, with a correct trajectory and no warning; `compute_all_sensitivities`, `steady_state(sensitivity_params=...)` and reported expressions likewise. The artifact now records which parameters were attached when it was built, and a sensitivity run builds it again when that has changed. A `run_batch` row whose own writes pin or re-attach a derived parameter is refused with `SensitivityUnsupportedError` when parameter columns are requested, since every row runs on the one artifact; make the write on the model before the batch, or run the row with `set_params` and `run()`.
