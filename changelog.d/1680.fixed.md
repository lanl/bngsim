- **SUNDIALS' warnings were written to the process's standard output ([#1680](https://github.com/lanl/bngsim/issues/1680)).** They pass by `sys.stdout`, `warnings` and `logging`, so a run that is right could put lines into the output of the script that called it: `A -> 0` at k = 1e9 from t = 1e6 wrote eleven `[WARNING] ... t + h = t on the next step` lines there, mixed into whatever the script printed or piped. They now go to standard error, where SUNDIALS' `[ERROR]` lines already went. `SUNLOGGER_WARNING_FILENAME`, SUNDIALS' own environment variable, still decides where they go when it is set: `stdout` puts them back, the null device drops them, and that holds too for the runs that drop their own warnings (a model with discontinuity or state-switch roots, KINSOL), which overrode it before. The solvers guide's Logging section says so, and that the variables are read once per solver context.
