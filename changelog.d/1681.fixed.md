- **An ODE run that starts far from t = 0 returned a wrong trajectory with no error ([#1681](https://github.com/lanl/bngsim/issues/1681)).** The integrator advances its clock by `t + h`, and far out the doubles are coarse: `A -> 0` at k = 1 over `(1e15, 1e15 + 10)` gave A(+5) = 0.00144 for 0.00674, and over `(1e17, 1e17 + 64)` A stayed at 1. A model that reads no clock (no function of `time()`, no table indexed by time, no event) is now run (`method="ode"`) on the time elapsed since its start (its end, for a run below 0 that starts over twice as far out), wherever the run's end nearer 0 is at 2^20 or beyond, and reports the times asked for: counted from its start, it is the run from 0, to the bit, where its start is on the spacing of the doubles at the far end (always, below 0), and as accurate where it is not. A run nearer 0 is unchanged. A failure of a moved run whose message names a time names it on the run's clock and says which time to add. A model that reads the clock keeps the absolute one, as before; a switch on a counter clock moves with the run, its switch time placed from the counter ([#1828](https://github.com/lanl/bngsim/issues/1828)); `run_diffrax` is not moved.
