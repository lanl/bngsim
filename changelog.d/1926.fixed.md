- **`Result.check()` no longer fails a correct run whose output points fall on or near a column's zeros (issue #1926).** The `"tolerance"` and `"sensitivity"` checks judged each column on its peak at the run's points. For `y = -sin(πt)` sampled at integer times that peak is the integration error, so a run right to 2e-5 moved 0.84 of it and was a diff. A column past the bound on that peak is now judged on its peak between the points too, on the grid check's run at 8x the points, and the verdict counts such columns in `n_between`. A default `check()` already makes that run; a narrower one makes it only where a column fails on its sampled peak.
