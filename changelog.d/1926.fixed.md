- **`Result.check()` no longer fails a correct run whose output points fall on or near a column's zeros (issue #1926).** The `"tolerance"` and `"sensitivity"` checks judged each column on its peak at the run's points. For `y = -sin(πt)` sampled at integer times that peak is the integration error, so a run right to 2e-5 moved 0.84 of it and was a diff. A column past the bound on that peak is now judged again, each point on the largest value the column reaches beside it on the grid check's run at 8x the points, which `n_between` counts. A spike between two points excuses only those two. A budget that runs out before that run makes the verdict a `timeout`.
