- **`mratio(a, b, z)` no longer returns a wrong value when `a` is a tiny
  positive number below a `b` under 1 and `z` is past -20 (issue #1793).** The
  continued fraction still ran there and lost up to all of the ratio:
  `mratio(1e-30, 2e-12, -3e4)` returned 7.047e-17 for 6.667e-17, and some
  answers had the wrong sign. The corner issue #1080 sums as two series out to
  `z = -700`, and leaves to the asymptotic expansion beyond, is now `0 < b - a
  < 1` with `b < 1`, which takes these too; the worst error there is 2.7e-14.
  At the subnormal doubles, where main was also wrong in places, by up to 61%,
  every answer is now right: the series sums its denominator times 2^54 where
  `alpha` or `alpha*z` is subnormal (`alpha = a` for `z > 0`, `b - a` for `z <
  0`), and forms a subnormal `b`'s last product the same way, so
  `mratio(5e-324, 1e-322, 10)`, 3.1e-3 off before, is now exact. Where `b` and
  `|alpha*z|` are both subnormal and `|alpha| >= 1`, the fraction, wrong there
  at 112 of 615 triples, is refused. Both engines. BNG's own arguments are
  unaffected, bit for bit.
