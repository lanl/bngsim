- **`mratio(a, b, z)` no longer returns a wrong value when `a` is a tiny
  positive number below a `b` under 1 and `z` is past -20 (issue #1793).** The
  continued fraction still ran there and lost up to all of the ratio:
  `mratio(1e-30, 2e-12, -3e4)` returned 7.047e-17 for 6.667e-17, and some
  answers had the wrong sign. The corner issue #1080 sums as two series out to
  `z = -700`, and leaves to the asymptotic expansion beyond, is now
  `0 < b - a < 1` with `b < 1`, which takes these too; the worst error there
  is 2.7e-14. At the subnormal doubles, where main was also wrong in places, a
  `b - a` below 2.2e-308 past `z = -20` is refused, as is a subnormal `b`
  beside a subnormal `alpha*z` (`alpha = a` for `z > 0`, `b - a` for `z < 0`),
  where `mratio(5e-324, 1e-322, 10)` was 3.1e-3 off, and the series no longer
  rounds the ratio away at any other subnormal `b`. Past `z = -700`, an `a`
  small enough that `a*(a-b+1)/(-z)` underflows (below 3.5e-321 at `z = -701`
  for `b = 0.5`) is now refused where the fraction answered, sometimes
  rightly: `mratio(5e-324, 0.5, -701)` was 7.138e-4. Both engines. BNG's own
  arguments are unaffected, bit for bit.
