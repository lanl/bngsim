- **A forward sensitivity to a parameter sitting on a kink of a rate law returned one side's slope, or neither** ([#1332](https://github.com/lanl/bngsim/issues/1332)). `0 -> X` at `10*abs(q) + s` with q = 0 has slopes of −47.62 and +47.62 in q at its steady state, and no derivative. bngsim returned dX*/dq = 0. `10*min(q, 1) + s` at q = 1 (slopes 47.62 and 0) returned 23.81. Both happened at a steady state and in a run, with no error. Such a column is now refused with `SensitivityUnsupportedError`, naming the parameter, the reaction and the bend (`abs`, `min`, `max`, `clamp`, `if()`). The check covers bends over parameters alone, at the values the run, steady state, batch row or `compute_all_sensitivities` call has (its default parameter set as well as a named one), so a `set_param` onto a kink after the `Simulator` is built is refused too. It is asked of the whole law, with each side of the bend put in for it: a parameter the bend does not move, a tie of arguments with one slope, and a law that has a derivative there all the same (`abs(q)*q` at q = 0, an `abs` in a branch the values do not take) are not refused.
