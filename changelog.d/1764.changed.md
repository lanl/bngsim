- **A pull request that adds a test file no check runs now gets a warning ([#1764](https://github.com/lanl/bngsim/issues/1764)).** `mir.yml` and the three Windows workflows run hand-picked test lists, and the `python-tests` legs build without what they have (MIR, MSVC, KLU on Windows), so a new file that only does real work there skipped on every leg, ran nowhere else, and left every check green. A new `python-tests` job, "New test files run somewhere" (`ci/new_test_coverage.py`), reads every leg's per-file counts and every other workflow's pytest commands and `pull_request` trigger. It warns, naming the file, when the pull request adds a test file that skipped on every leg and that no workflow running on that pull request runs, and says which lists and paths filters it could join. A workflow counts only when its paths filter fires for the change, so `forced-jit` and `sanitizers` (whole suite, nightly) count only when the change edits their files; an argument it cannot read (a shell array, a matrix value, `-k`) never counts. It warns rather than fails, as does a missing or unreadable report.
