- **On arm64, a MIR-compiled leaf function with enough live integer values could return to the wrong address.** MIR's register allocator may give x30, the link register, to a value, because the prologue and epilogue save and restore it. But MIR skips both for a leaf function that needs no callee-saved register and no stack slot, so such a function returned to whatever x30 held last. A function whose integer values filled every caller-saved register, x30 included, without needing a callee-saved one crashed with SIGBUS at every MIR level. A local carry in `third_party/mir/mir-gen-aarch64.c` keeps the prologue and epilogue when x30 is used. Functions that do not use x30, and x86-64, are unchanged. Found in the review of #1575.
